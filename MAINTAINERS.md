# Maintainers

Maintainers protect the project's parser contracts, community health, security
posture, and release quality. The list below records current public ownership;
it is not a claim that every GitHub setting has been configured accordingly.

The repository also lists the maintainer in [CODEOWNERS](.github/CODEOWNERS).

## Maintainer responsibilities

- Keep the source-of-truth and deterministic parsing contracts explicit.
- Review changes that affect public APIs, filesystem writes, security, or
  release artifacts with the appropriate evidence.
- Keep documentation, issue decisions, and release notes consistent with the
  code that is actually shipped.
- Welcome contributors and give clear, respectful feedback.
- Protect private vulnerability reports and coordinate fixes through
  [`SECURITY.md`](SECURITY.md).

## Becoming a maintainer

Maintainer consideration is based on sustained contributions, sound technical
judgment, helpful reviews, reliable participation, and agreement with
[`GOVERNANCE.md`](GOVERNANCE.md) and the
[Code of Conduct](CODE_OF_CONDUCT.md). There is no automatic promotion rule;
the current maintainer records the decision and its scope.

## Succession and resilience

The project should add an independent reviewer before introducing rules that
depend on a second approval. Until then, security, release, and governance
decisions remain explicitly maintainer-owned and are documented in the
corresponding issue, pull request, or release record.
