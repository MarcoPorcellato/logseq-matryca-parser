# Public roadmap for 2026–2027

This is the public navigation view for the GitHub and AAIF readiness programme.
The detailed evidence, exclusions, and historical anchors remain in the
[readiness study](REPOSITORY_GOVERNANCE_AAIF_STUDY_2026-08-19.md). It is a
roadmap, not a release promise or an AAIF submission claim.

## Status vocabulary

| Status | Meaning |
|---|---|
| Completed locally | Source changes and local checks are complete; publication is recorded separately |
| In progress | An owner is actively working within a defined scope |
| Waiting for evidence | Requires current external, release, security, or adoption evidence |
| Deferred | Intentionally postponed until a dependency or user need exists |

## Milestones

| Milestone | Status | Owner | Dependency | Exit evidence |
|---|---|---|---|---|
| M0 — Public baseline | Waiting for evidence | Maintainer | Valid GitHub API access | Exact `main` SHA, rulesets, Actions permissions, security features, and issue/PR/project receipt |
| M1 — Governance minimum | Completed locally | Maintainer | Documentation review | Governance, maintainers, support, citation, and AI-contribution documents linked and passing the docs gate |
| M2 — Supply-chain proof | Implemented locally; waiting for hosted receipts | Release owner | M0 and a real tag | Dependency review and Scorecard runs plus verified release SBOM, inventory, checksums, and attestations |
| M3 — Documentation convergence | Migration gate recorded | Documentation owner | Matryca Knowledge profile decision | Current provenance references, dual-profile audit, and reviewed projection evidence without rewriting history |
| M4 — Semantic assurance | In progress | Parser owner | Exact-head parser evidence | Compatibility corpus, adversarial profiles, cold/incremental equivalence, and invariant-preserving test receipt |
| M5 — Community durability | In progress | Maintainers | M0 and sustained contributor activity | Triage policy, current label taxonomy, public roadmap, response measurement, and independent reviewer path |
| M6 — Interoperability and adoption | Deferred | Product and community | M4 and permissioned use cases | Threat model, adapter conformance, and permissioned downstream evidence |
| M7 — AAIF decision gate | NO-GO recorded | Maintainer and legal reviewer | M0–M6 | A future reconsideration record supported by a completed evidence matrix |

## Current delivery focus

1. Restore GitHub API access and record the public baseline without changing
   repository settings.
2. Publish the locally implemented dependency-review, Scorecard, release
   evidence, and metrics-hardening changes through normal review.
3. Qualify the supply-chain contract on a real tag; local generation does not
   substitute for hosted attestation verification.
4. Keep documentation and the Matryca Knowledge source profile aligned through
   reviewed source and projection changes, preserving the measured official
   OKF backlog until the profile conflict is resolved.
5. Continue parser assurance only through exact-head, invariant-preserving
   evidence and apply triage policy only after live GitHub state is read.

## What this roadmap does not promise

- a date for an MCP or A2A implementation;
- a security, release, or AAIF claim without independent evidence;
- a second maintainer before a qualified person accepts that role;
- a release schedule or feature commitment merely because an item appears here.
